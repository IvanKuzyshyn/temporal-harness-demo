# Temporal Agent Harness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Execute autonomously, with test-first development, isolated worktrees and orchestrator review.

**Goal:** Deliver the user's complete local Temporal agent teaching harness as an unmerged linear stack of 18 draft PRs.

**Architecture:** Temporal owns durable workflow state; activities perform I/O. Local artifacts hold transcripts and command logs; sequenced JSONL is a lossy display channel. TUI reconnect reconciles against authoritative workflow snapshots.

**Tech Stack:** Go 1.27.3, Temporal CLI 1.10.0, Ollama 0.40.15; pinned stable Go SDKs and Charm v2 components verified from source before use.

**Spec:** User's implementation prompt, sections 0–13, supplied in the implementation session. It is the binding authority; this plan records execution order, not a replacement specification.

## Global Constraints

- Never merge, push main, mark ready, or enable auto-merge. All PRs draft.
- PR1 targets main; each subsequent PR targets its predecessor branch.
- At every stack position run `go build ./...`, `go vet ./...`, `go test ./...`; CI uses mock, no cloud credentials.
- Worktrees per parallel implementer; disjoint file ownership. Orchestrator reviews diffs and independently verifies before integration.
- No workflow I/O, wall clock, randomness, goroutines, or nondeterministic map iteration. Use workflow primitives.
- Unsafe activities have MaximumAttempts 1, require approval, and return interrupted results after worker loss.
- Resolve symlinks and pin workdir; argv only, never a shell. Allow only go test/build/vet, ls, cat, git status/diff, with constrained arguments.
- No credentials, tokens, or .env files in commits.

## Review Focus

- Path containment under symlink changes and non-existing write targets: tools tests.
- Command flags that execute programs or access outside workdir: tools tests.
- Partial JSONL records and cross-process concurrent writers: events tests.
- Cancellation during approval and stream retries: workflow and activity tests.
- Queued Updates across Continue-As-New and stale reconnect events: workflow/client tests.

## Parallel ownership

W0 is orchestrator-only (01–02). W1 dispatches devenv, llm, events, tools, sample independently against contracts. W2 dispatches workflow/worker/client versus TUI fake-client. W3 dispatches LLM activity, parallel workflow helpers, child workflow and command activity. W4 dispatches approval, inbox/failures, and noninteractive CLI with disjoint seams. W5 integrates sequentially.

Subagents never push, open PRs or merge. They commit only their scoped files and report tests and API deviations. The orchestrator cherry-picks onto the preceding stack branch, reviews, reruns gates, pushes only the feature branch, opens a draft and updates previous/next links.

## Rulings

- The supplied design and explicit autonomous mandate waive further design/plan approval pauses.
- The user explicitly requires parallel isolated implementers, overriding the generic skill's sequential-only preference.
- `land contracts` means publish a draft contracts PR, never merge it.
- Pi print-mode subprocesses provide isolated agent contexts when no native subagent tool is exposed.
