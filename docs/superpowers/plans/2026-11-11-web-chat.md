# Durable Web Chat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the terminal coding demo with a local web chatbot whose execution, approvals, cancellation, and recovery remain Temporal-driven.

**Architecture:** Next.js is the browser-facing UI/proxy; a Go API owns application persistence and durable command dispatch to existing Go Temporal orchestration. Postgres holds application history and separate Temporal databases, while a persistent file store holds original attachments. Model/tool execution stays in activities, with scoped document-analysis children and bounded parallel work.

**Tech Stack:** Existing pinned Go/Temporal SDK/Ollama; Next.js App Router, TypeScript, Tailwind, accessible component primitives, Node/pnpm; Docker Compose/Postgres/Temporal; Go pgx database access, SQL migrations, Vitest and Playwright. Exact new dependency versions are qualified and pinned in Task 1.

**Spec:** [Proposed design](../specs/2026-11-11-web-chat-design.md). Both documents were approved for implementation on 2026-11-11, including the mise lifecycle amendment.

## Global Constraints

- Single-user local demo; loopback-only access, no login, no public deployment.
- Required user lifecycle: `mise run setup`, `mise run up`, `mise run down`. Setup prepares tools/dependencies/models; up starts all required services; down stops only project-owned services and preserves all persistent data.
- Models: `qwen3.5:9b` by default and `gemma4:e4b`; fixed per conversation, no silent fallback.
- Keep all four Temporal patterns executable: long-running activities, parallel execution, child workflows, recorded approval.
- Clean start: no old transcript migration or legacy workflow compatibility promise. Do not delete `.data/` or disturb existing services.
- New workflow type `WebChatSessionWorkflow`; queues `web-chat-agents`, `web-chat-llm`, `web-chat-documents`.
- No network/filesystem/database I/O in workflow code. Keep payloads bounded and reference large content by stable IDs.
- Tools are `web_fetch` and `file_upload`; no search engine, shell commands, repository writes, or OCR service.
- Approve once binds one action; Approve all applies to the versioned current toolset in one conversation and is revocable. Default approval expiry is 24 hours.
- Attachments: TXT/Markdown/PDF/DOCX/PNG/JPEG/SVG, 1,048,576 bytes per file, maximum four per message. Original file bytes persist outside Postgres; metadata and extracted text persist in Postgres.
- Context target 16,384 tokens; text input estimate ≤12,000, output cap 2,000; image reserve is qualified, not assumed. Six recent exchanges, summary ≤approximately 1,500 tokens, excerpts ≤approximately 4,000 tokens, all subordinate to the total budget.
- One active turn per conversation. Replacement cancels and joins current work before starting; replacement precedes previously queued normal follow-ups.
- Default safe concurrency four, default model concurrency one, maximum 12 agent steps per turn, document child timeout 15 minutes.
- Durable history is never reconstructed solely from display events. No success until required persistence succeeds.
- Keep API contracts and schema under version control; Next.js does not directly write application tables.

## Review Focus

- Browser/API retry after an ambiguous response must not duplicate a user turn, including across Continue-As-New — Tasks 3–4.
- Replacement racing with an approval or a completed turn must not cancel the wrong turn or start overlapping work — Tasks 5–6.
- Tiny compressed files, hostile SVG/HTML, redirect/DNS tricks, and cross-conversation attachment references must not escape local boundaries — Tasks 7–9.
- Slow or reconnected clients and restarted model attempts must not splice drafts into another turn or certify completion from a stale stream — Tasks 4, 11–12.
- History summarization and image/document limits must not silently discard evidence while claiming full context or complete document coverage — Tasks 9–10, 14.

## File and responsibility map

New backend boundaries:

- `cmd/web-api/main.go`: Go HTTP API and command dispatcher lifecycle.
- `cmd/web-worker/main.go`: dedicated Temporal workers, no TUI/dependency autostart.
- `internal/chat/contracts.go`: shared application IDs, records, statuses, command/approval enums.
- `internal/storage/{postgres,conversations,messages,commands,attachments,events,summaries}.go`: SQL repositories, transactions and idempotency.
- `internal/api/{server,conversations,commands,attachments,events,security}.go`: HTTP validation/serialization and private API authentication.
- `internal/dispatch/{dispatcher,reconcile}.go`: Postgres command outbox to Temporal dispatch/recovery.
- `internal/attachments/{store,validate,extract,images,svg}.go`: file storage, bounded parsing, model image preparation.
- `internal/context/{builder,summary,budget}.go`: model-input selection and budget accounting.
- `internal/tools/{web_fetch,attachment_analysis,web_registry}.go`: only approved web-chat tools.
- `internal/workflows/{web_session,replacement,document_analysis}.go`: new workflow lifecycle and scoped children; reuse/adapt existing helpers where compatible.
- `internal/activities/{chat_persistence,chat_model,document_analysis}.go`: database/model/document I/O adapters.
- `migrations/app/*.sql`, `compose.yaml`, `.env.example`: reproducible service and schema setup.

Web application:

- `web/app/page.tsx`, `web/app/chat/[id]/page.tsx`: entry and conversation routing.
- `web/app/api/[...path]/route.ts`: allowlisted Go API proxy, uploads and unbuffered SSE.
- `web/components/{chat-shell,conversation-sidebar,message-list,composer,approval-card,attachment-picker,tool-details}.tsx`: presentation and user actions.
- `web/lib/{api,contracts,event-reducer}.ts`: typed transport and identity-based reconciliation.
- `web/tests/`: component/reducer tests and Playwright E2E.

Lifecycle: `scripts/dev/{setup,up,down}.sh` and a shared ownership/health-check helper behind `mise.toml`; lifecycle tests under `scripts/dev/tests/`. Ignored runtime logs/ownership records must never contain committed secrets.

Cross-cutting: `docs/web-api.md`, `docs/web-chat-operations.md`, `docs/web-chat-qualification.md`, `.github/workflows/ci.yml`, `scripts/test-web-integration.sh`.

These are ownership boundaries, not permission to create large miscellaneous files. Test files live beside Go sources or under the frontend test directory.
