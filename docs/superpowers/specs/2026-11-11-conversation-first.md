# Conversation-first terminal correction

## Approved intent
The user reported that their prompts and assistant responses look identical, internal output overwhelms the conversation, and outcomes lack useful color separation. They approved the proposed correction and explicitly authorized implementation on top of existing open PRs. This is an iteration of the approved chronological HTML sketch, not permission to replace it with another plain record dump.

## Binding presentation
- Normal conversation shows user prompts and substantive assistant responses, not generic Record N labels, hashes, context envelopes, tool arguments or raw logs.
- User messages: cyan/blue bold `You` heading, distinct left marker and vertical separation. Assistant: distinct bold `Assistant` heading; long body neutral/readable. A completed response has a green heading/check with wording that means response completion, NOT verified tests. Failed requests/commands have red textual labels; approval/interrupted/unknown uses amber. Never derive outcome from prose or repository bytes. Labels/spacing preserve meaning without color.
- One compact expandable work block per prompt groups automatic context, intermediate tool-request assistant messages, tool results, child work and noisy live progress. Collapsed by default, with a short factual summary/count/current activity. Raw details remain available by explicit expansion and existing bounded detail/log controls. The conversation remains readable with a large context record and many tool events.
- Failures remain visible as concise notices even when work is collapsed. Approval remains a dedicated safety interlock, never hidden in a collapsed block. Expanding work must not send messages or trigger approvals.
- The approved HTML terminal section is the layout reference: compact aligned identity, distinct activity/history region, spaced role entries/receipts, persistent visually separated composer. Translate these into terminal cells; don't recreate browser framing/buttons/fonts. On normal80x24, normal header is at most5 rows (excluding exceptional warnings), not the old10-row stack. Original model/root/session remain identifiable; full metadata accessible. Suppress empty queue and stale success-submit chatter from normal chrome.
- Composer stays pinned at80x24 and120x40, retaining multiline draft across updates/navigation/resize. Preserve safety at tiny sizes. Maintain original session authority, durable page/history identity, log scope, frozen browsing/reflow anchors, unseen updates and explicit End/latest policy. Expanding groups must not invalidate record identity or confuse selected IDs with rendered indices.

## Honest grouping and bounds
Grouping is a display projection of the bounded loaded transcript page, never a rewrite of history. Associate by actual message order and durable IDs, not reused tool-call IDs or text. A page starting midway through a prompt must label preceding work as partial/earlier rather than attach it to an unrelated prompt or invent a complete count. Later user messages begin their own group. Expanded state is bounded by the loaded page and resets appropriately on session/source/window replacement; latest refresh keeps same-page group identity. Lossy live events remain observations, retire as before, and cannot certify execution outcomes. Query failure without durable run association must not falsely recolor an old response.

## Scope and compatibility
Native Go/Bubble Tea/Bubbles/Lip Gloss only; no dependency upgrades, new runtime dependencies, workflow/activity/provider changes, replay fixture replacement or backend control API changes. Keep all existing published PRs draft/unmerged, preserve main and user's checkout/edit. Branch from draft22 into a new draft PR. No default-service restarts. Repository content remains untrusted data; real command outcomes use the existing strict parser.

## Acceptance
Content-level tests must assert hidden noise, visible prompts/answers/failures, distinct semantic roles/colors, group expansion, partial pages and bounded state—not just boolean flags. Update layout/navigation tests to new visible-group geometry without deleting their safety assertions. Serialize expensive suites with -p1. Independent review checks source plus approved requirements.

Actual PTY captures must show a complete representative prompt → collapsed work → response at80x24 and120x40, plus expanded work, failure, active work and approval. Capture with real native renderer and keystrokes. Controlled fixture content is labeled as such; actual events/outcomes must not be fabricated. Compare actual decoded terminal cells/PNG against the approved sketch and the three user complaints, using a separate visual evaluator. Functional gates alone cannot pass visual acceptance. Report mismatches instead of declaring victory based on spinner/pinned-input tests.
