Document analysis executes real children. Task9 continuation1 adds the [source-bounded narrow production image profile](web-chat-image-profile.md): exactly one640×160 normalized PNG, bounded ASCII instruction, no optional history/tools, pinned Ollama0.40.15/MLX and exact model digests. Authorized PNG/JPEG/safe-SVG requests and newly approved image follow-up after worker/store restart are verified through the actual application/provider/SQL path.

Global arbitrary-image admission remains unqualified: `imageAdmissionQualified:false` and all earlier Qwen failure recordings are unchanged. No fallback/OCR exists. Unresolved references, unsupported envelopes and runtime/model/profile mismatch reject before inference. Normalization may lose detail and the ASCII-only instruction profile is intentionally narrow, not universal quality certification.

## Durable contracts for Task10/UI

Schema **7** adds `document_analysis_parts`: immutable `(tool_call_id, part_index)` rows, full approved input identity, canonical result and owning physical invocation UUID. Index **-1** is the extraction manifest; **0..31** are chunk summaries and byte coverage. These are not display events or filename caches. Original/extracted text and summaries stay in storage, never activity return payloads or workflow history.

- `chat.DocumentAnalysisInput{Scope, Model, Budget}` contains only references. Its scope binds conversation, turn, tool call, immutable checksum, canonical instruction/action hash, tool/toolset versions and policy revision. The actual instruction and attachment ID are resolved from the persisted authorized tool arguments, not supplied afresh by a child.
- `DocumentAnalysisWorkflow(ctx, input) (chat.DocumentAnalysisResult, error)` runs on `web-chat-documents`. Deterministic ID: `document/<tool-call-UUID>/<action-hash>`. Parent-close request-cancel, wait-for-cancellation, no workflow retries/new logical attempt series, **15-minute execution timeout**.
- `DefaultDocumentBudget()` is immutable **32 chunks**, **4000 UTF-8 bytes/chunk**, **four bodies at a time**. Smaller final chunks never split UTF-8 sequences. The production runner shares one generation gate across chat and document activities; parser/DB/activity work can overlap. Multiple worker processes have separate gates; run one production worker for the local-hardware default.
- Activities: `PrepareDocumentAnalysis`, `AnalyzeDocumentChunk`, `FinishDocumentAnalysis`, and `AnalyzeAttachmentImage` for profile-bound image manifests. Every physical body, including retry attempts, registers before reads/cache/model work and acknowledges only after normal body return and joined heartbeat/shutdown work. No arbitrary tools, URLs, attachment selection or filesystem paths are accepted by the child.
- `WebToolResult.analysis`: `childId`, `chunks`, `truncated`, `status` (`completed`, `partial`, `unsupported`). `coverage` entries currently use Go JSON field names `Index`, `StartByte`, `EndByte`, `SummaryTruncated`. They are ordered by chunk index even when activity completions/SQL commits occur in reverse order. Coverage is **UTF-8 byte offsets in canonical extracted text**, not parser section offsets (which remain Unicode-character offsets). `pages`, `extractionStatus`, `error`, and `truncated` are retained.
- Each chunk summary is bounded to **1000 UTF-8 bytes**, aggregate tool text to **16000**, then the existing request builder admits at most **4000 combined excerpt bytes**. Truncation at extraction, chunk-count, summary, aggregate and request-excerpt stages is explicit; never imply full document coverage when `truncated` is true.
- Output exhaustion is separate from source coverage: `Tokens >= 2000` conservatively sets the chunk's durable `SummaryTruncated`, even for a short visible answer (thinking may consume the budget). Finalization propagates it to `analysis.status:"partial"` and both truncation flags. Byte offsets still describe the source chunk; they do not certify a complete summary.
- A summary must contain non-whitespace UTF-8 text after the1000-byte clipping. Blank/empty model output is an invalid result, not completed coverage: no chunk summary is saved, the child fails, and ordinary parent settlement records a failed turn/tool result without completed analysis. Storage rejects unusable chunk writes and reads; activity retry/finalization also reject invalid cached summaries rather than rewriting immutable history. Index-1 metadata manifests may legitimately have empty text. Image analysis likewise rejects whitespace-only new model output; its existing token-cap partial handling is unchanged.
- No new HTTP endpoint is introduced for partial chunk rows. Internal repository consumers can read authorized `ReadDocumentPart`; the existing model reads only the final canonical `WebToolResult`. A future UI/projection API must preserve ownership and distinguish durable partial rows from a completed analysis.

Step0 attachment preflight runs before inference. It binds the actual user text as the instruction (empty text defaults to “Describe this attachment.”). The tool's existing **4096-byte instruction bound** is enforced; oversize instructions are rejected, not silently shortened. Denial/expiry reads no original content. A later model `file_upload` call is a new action and obtains its own exact authorization. Cached extraction does not authorize a new instruction.

Each chunk uses the conversation's exact stored model. Full JSON-escaped message bytes, framing and prompt must fit **12000** conservative text-input units, plus **2000 output** and **2384 reserve** in **16384** context. There are no tools in a chunk request. Oversize mandatory context fails before inference; there is no reliance on provider truncation. No Task10 historical summarization is included.

## Cleanup and retry semantics

Child activity invocations join the existing turn-local tool ledger. Distinct document phases use a fixed ledger generation; immutable per-part ownership, not cross-phase retry numbers, fences chunk publication. Finalization is the only phase that publishes the tool result. A retry adopts another body's canonical persisted part but cannot rewrite its own winning result.

The parent first joins the child future, then seals registration. Accepted stop/replacement requires **zero missing ACKs across every model/tool/document body**, including an earlier timed-out attempt whose logical retry has already ended. Positive counts leave the target `cancelling`/`cancelling_interrupted` and replacement queued. The parent rechecks durable counts every five seconds; only a real ACK can permit progress. Time itself is not join proof. If an ACK never arrives (hard death/uncertain parser cleanup), intervention remains blocked. Workflow cancellation during a recheck is not relabeled persistence failure.

Ordinary retry-safe recovery without accepted control remains distinct: a missing old ACK does not veto canonical completion. Worker/store restart during child inference retries the unfinished chunk and preserves the action/manifest. Successful chunks are immutable and reused; failed child runs do not start a fresh child under a new identity to bypass budgets. Partial rows remain durable even when the turn fails. A cached exhausted summary retains its partial flag through retry/adoption and finalization; it is not regenerated into an apparently complete result. Previously persisted nonempty summaries that lost exhaustion evidence cannot be retroactively classified from text alone; this fix does not rewrite immutable historical results. Invalid legacy blank chunk rows now fail closed.

## Raster preparation and separately bounded admission

`llm.ImageReference{AttachmentID, DerivedKey, Checksum}` is opaque. `Store.ResolveImage(ctx, ApprovalScope, reference)` authorizes before any metadata/cache/original lookup, rechecks ownership/checksum and returns an activity-local `ResolvedImage`. Derivation keys are `model-png-v1` (preparation only) and `ollama-0.40.15-mlx-640x160-v1` (fixed narrow raster), never arbitrary paths. PNG/JPEG headers are checked before decoding: at most **8192** per dimension and **20,000,000 pixels**. Model-preparation raster is PNG, at most **2048** longest side and **1MiB** encoded. Oversize derived output is rejected, not silently enlarged. Resizing currently uses deterministic nearest-neighbor sampling; no vision-quality certification is implied.

SVG uses the pinned maintained saxes/resvg helper, with formatted named validation callbacks. Its narrow static-vector policy is unchanged: no text/fonts/CSS/href/images/use/filter/animation/scripts/entities/external loads. `Rasterize` returns PNG only. Original SVG remains attachment/nosniff, never active inline HTML. Actual Docker-inspect tests verify no network/mounts, read-only/nonroot,512MiB memory+swap,1CPU/8CPU-seconds,32PIDs,cap-drop ALL/no-new-privileges. Operation deadline is10s; bounded independent create/cleanup joins can extend wall time (cleanup up to15s), and uncertain cleanup never becomes an ACK. The narrow profile additionally letterboxes/downsamples to exactly640×160 and performs source-backed model/context admission; see its separate contract above.
