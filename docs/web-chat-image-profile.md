## Admission contract

1. Upload is not authorization. `PrepareDocumentAnalysis` resolves only authorized metadata and durably binds the profile in the action's manifest. `AnalyzeAttachmentImage` registers each physical body in the existing invocation ledger, verifies immutable scope/model/instruction/manifest, and validates the mandatory request **before original resolution**. It adopts an already persisted result without rereading bytes. Otherwise `Store.ResolveImage` independently authorizes the exact owned attachment/checksum again before content access.
2. Original PNG/JPEG and constrained SVG raster retain the existing 1MiB/20MP/8192-per-dimension limits. The authorized preparation first bounds a raster to2048 longest side, then aspect-preserving downsampling (never enlargement), opaque white compositing and letterboxing produce **exactly640×160 PNG**, at most1MiB. The image itself may lose detail, especially portrait/extreme-aspect sources; no semantic quality guarantee follows from safe resource admission. Old `model-png-v1` is still a preparation primitive, never a production inference profile.
3. Exactly one image, one fixed system message and one user instruction. No optional history, arbitrary tools, schemas, extra messages or media. Instruction is1..4096 printable ASCII bytes (also tab/CR/LF), further restricted by the total context bound; non-ASCII instructions explicitly reject. Text containing `[img-` rejects because upstream expands every literal `[img-N]` into media work; `<|` control-token sequences also reject. Source image text is not restricted to ASCII.
4. Use the exact upstream renderer (`qwen3.5` or `gemma4-small`) with `think:false`. Let `R` be its complete rendered prompt's byte length, including system/user/assistant framing and the image marker. Admission requires:

   `3*R + 512 + imageTokens + 2000 output + 2384 reserve <= 16384`.

   The pinned Qwen tokenizer normalizes NFC, which does not expand ASCII; Gemma replaces each space with three-byte `▁`. Their BPE/byte fallback cannot emit more tokens than normalized bytes. The explicit512 allowance covers BOS/prefix/framing conservatively in addition to counting the actual renderer and the separate2384 context reserve. There are no hidden default system/messages layers in these pinned manifests. Transport JSON escaping/base64 is not confused with language tokens. At the measured unit-test boundary repeated `x` instructions admit3511 bytes for Qwen or3598 for Gemma (full bound16383); one more byte rejects **before provider I/O**.
5. Adapter revalidates the whole envelope, reference equality, PNG encoding and exact dimensions. Every image dispatch checks `/api/version == 0.40.15` and `/api/tags` for the exact selected tag, digest, MLX runner, safetensors format and no remote model. No cached qualification survives changes. Wire requests explicitly select `runner:mlx`, `num_ctx:16384`, `num_predict:2000`, `think:false`, `truncate:false`, `shift:false`. Runtime/model/profile mismatch rejects; requalification requires a new profile, not relaxing this one. These are checks of the trusted local provider's identity, not remote software attestation or protection against a malicious replacement reporting the same version/digest. Do not mutate local model tags during inference.
6. Each image body has a90-second deadline, at most two logical attempts under the existing child budget, heartbeat/shutdown joins and the turn-local physical cleanup ledger. A single production runner serializes model generation across chat/document/image work. Provider MLX uses native model maximum context internally; our explicit pre-dispatch16K bound and2000-token output cap establish the application limit independently of provider history truncation. This does not certify a hard cap on total GPU RSS or GPU reclamation after cancellation.

## Durable interfaces and cleanup

`llm.ImageReference{AttachmentID,DerivedKey,Checksum}` stays opaque in messages. `llm.Request.Image` is activity-local `ResolvedImage{Profile,Reference,PNG}` and has `json:"-"`; original/derived bytes never enter Temporal parameters, return payloads or durable model history. The canonical tool result stores only model-produced text and `analysis.imageProfile`, along with child ID/status/truncation. Model and authorization identity remain in the immutable action/turn. Existing schema7 suffices; no migration or public endpoint is added. A manifest is **not** proof of completed image inference; only the canonical final tool result is.

Workflow: authorized preflight/file_upload → deterministic `DocumentAnalysisWorkflow` → `PrepareDocumentAnalysis` profile manifest → `AnalyzeAttachmentImage` → authorized original/SVG helper → normalized raster → selected adapter/provider → immutable SQL tool result → reference-only child completion. Text/PDF/DOCX still use bounded document chunks. The parent consumes persisted summaries, never silently rereads images while rebuilding history. A new instruction or attachment follow-up creates a new action requiring valid approval. Once authorization cannot be inferred from the existence of a cached result or a previously approved checksum.

Image bodies use exactly the document physical-join wrapper. Accepted stop/replacement waits for logical child cancellation **and every body's real cleanup ACK**, including earlier timed-out retries. Ordinary retry-safe recovery remains distinct. A winning immutable result is reread after publication; losing retries do not return their own alternate output as canonical.
